# API contracts

## Public article detail projection

`get_public_article(p_slug text)` returns `{kind: "notFound"}` for malformed, unknown, draft, archived, or deleted slugs. Published articles with invalid documents or unavailable required references return `{kind: "unavailable"}`; valid ones return `{kind: "ok", article}`. The allowlisted article includes its canonical document, public taxonomy and credits, and descriptors for finalized current images. It excludes storage paths and private identity, workflow, and history fields. The server adapter validates the response with a cookie-free publishable-key client and disables fetch caching. This interface does not grant public object access or implement a reader page. See the [Task 2 plan](superpowers/plans/2026-11-09-public-article-projection.md).

## Public article lists

`list_public_articles(scope, primary, secondary, limit, cursor)` returns bounded published-only cards for latest, section, section/category, tag, and owner-or-contributor author scopes. Limits are 1–24; the server adapter defaults to 12. Cards contain title, excerpt, publication timestamp, public section/owner/writer fields and a finalized main-image descriptor. They omit article bodies and private metadata. Cursors bind scope and filters, preserve timestamp microseconds, and are not authorization; malformed or mismatched requests return `invalid`. Database failures and invalid results return `unavailable`. New requests recheck publication and may see changes between pages. The server uses the cookie-free, no-store public client. See the [Task 3 plan](superpowers/plans/2026-11-09-public-article-list.md).

## Reader navigation endpoints

Added by the [reader refresh plan](superpowers/plans/2026-11-13-reader-refresh.md#follow-ups-2026-11-13).

- **`GET /api/public/search/suggestions?q=`:** typeahead for the navigation search.
  - It calls `suggest_public_articles(p_query)`: published titles that contain the typed text, case-insensitive, newest first, at most 6. Partial words match, and typed `%` and `_` are literal.
  - The query is normalized like search and must be at least 2 characters. Each admitted call spends a typeahead ticket. Typeahead has 40 tickets per server minute and its own database lock.
  - Cards go through the same allowlisted `homepage_card_map` projection as search; the route returns only `{title, slug, section}`.
  - `ok` returns `{kind: "ok", items: [{title, slug, section}]}` with `Cache-Control: public, max-age=30, s-maxage=30`.
  - `invalid` returns 400, `rate_limited` returns 429 with `Retry-After`, and `unavailable` returns 503; all three are `private, no-store`.
  - The client waits for a 300ms pause and at least 2 characters, and aborts stale requests.
  - Full-text `/search` stays whole-word.
- **`GET /api/session/desk`:** tells the reader whether to show the staff desk shortcut.
  - It returns `{desk: null}`, or `{desk: {displayName, role}}` for the caller's own active membership. Responses are always `private, no-store`.
  - Requests without a Supabase auth cookie are answered without contacting Supabase.
  - The route handler can persist a refreshed session cookie. That's why the check lives here and not in public Server Components, which skip session refresh.

## Public tag archive resolution

`getPublicTagArchive(slug,cursor?)` resolves a unique tag through the anonymous tags policy, which exposes only tags with a public article, selecting only name/slug and validating the bounded response. It then uses the unchanged tag scope of `list_public_articles` with twelve-card pages. Missing tags and tags with no public articles produce a real route 404. A valid continuation can be empty if matches disappear between pages. Malformed/cross-tag cursors produce safe recovery and noindex, while backend/response errors are unavailable/noindex. Metadata/page share only the current request's result. Tags have no active flag; publication, active section/owner and association filtering remain authoritative in the list SQL. No public association-table read or write grant is added. See the [Task 14 plan](superpowers/plans/2026-11-10-public-tag-archives.md).

## Public author archive resolution

`getPublicAuthorArchive(slug,cursor?)` uses existing anonymous active-only profile RLS and selects only display_name/slug/biography with active=true. The checked public DTO contains displayName/slug/biography; no Auth ID, email, membership/role or workflow field is selected or returned. It reuses twelve-card author-scope lists, deduplicating published ownership and contributor credits through existing SQL. Active guests/empty archives remain valid; missing/inactive profiles share real 404, including for signed-in owners. Inactive membership alone does not retract an active biography or published journalism. Scope-bound cursor failures and unavailable responses remain safe/noindex; metadata/page share only one request's result. No migration, grant expansion or profile-image behavior is introduced. See the [Task 15 plan](superpowers/plans/2026-11-10-public-author-pages.md).

## Implemented private draft main image

`request_article_image_upload(articleId,requestId)` reserves an opaque media asset for an authorized draft/published owner or active administrator. `POST /api/articles/[id]/media/[assetId]` accepts one bounded multipart `file`, validates and re-encodes JPEG/PNG/WebP to private WebP, then uses the server-only service role to finalize the checked reservation. `set_article_main_image(articleId,expectedVersion,requestId,assetId,altText,credit,caption)` attaches a finalized same-article asset or unlinks with null asset/metadata. Caption is optional, trimmed, at most 400 characters, and empty input becomes null. Caption is bound into exact retry fingerprints and returned in main-image reads and published article detail. It returns the existing draft write result envelope, creates history on a change, and replays exact requests. These interfaces leave the Phase 3 draft payload and receipts unchanged.

`removeUnusedArticleImage(assetId)` first calls the user-scoped `mark_article_image_for_removal` RPC, then uses the server-only credential to remove the private object and call `complete_article_image_removal`. Who may remove is decided by `private.article_authority` (an author on their own unsubmitted draft, an editor on an article in review, an administrator on any draft or published article); archived articles reject new removal marks. Current body/main-image links and retained revision references block removal; unfinished (`pending`/`uploading`) assets can be marked. Actor, article and asset locks serialize reference changes with removal. An interrupted cleanup retains `deleting` for an authorized retry; trusted completion independently checks current actor authority, references and object absence.

The editor removes an unused image by its known asset identifier after explicit confirmation. Daily expiry handles unattached uploads that no longer have an editor control. The obsolete upload-list RPC has been removed.

## Task 4 private body images

The existing `save_article_draft(articleId,expectedVersion,requestId,draft)` accepts canonical `gavel-draft` version 2 bodies with image blocks containing only `assetId`, required alt text (1–240 characters), and optional caption (1–500 characters). Version 1 bodies remain valid. Database save checks each asset is finalized for that article and reconciles body references in the same transaction as content, revision, audit, and retry receipt. Video embeds remain unavailable pending a provider allowlist.

## Style and ownership

Use typed Next.js server actions for dashboard mutations where appropriate and route handlers for URL-addressable operations such as search or OAuth callbacks. Supabase remains an external data boundary protected by grants and RLS.

Authoritative request schemas will live beside the implemented server operations and be shared with form validation where safe. Database migrations remain authoritative for stored constraints. Avoid maintaining conflicting schema copies.

## Conventions

- Content type: JSON for application operations; multipart or signed upload flows for approved media.
- Identifiers: UUIDs internally; normalized slugs for public routes.
- Time: UTC ISO 8601 at interfaces and `timestamptz` in PostgreSQL.
- Missing optional values use omission or explicit null according to the operation schema; do not overload empty strings.
- Pagination uses bounded page/cursor inputs and returns items plus continuation metadata.
- Public listing defaults to newest published first unless a curated order applies.
- Mutations require an authenticated server session, active membership, and role/ownership authorization.
- Errors use stable codes, safe messages, field details where useful, and a correlation identifier. Internal details remain private.
- Retried mutations must not create duplicate publication, deletion, or audit effects.
- Apply operation-specific rate limits.

## Implemented foundation interfaces

- `/sign-in` starts Google OAuth through a server action; the `bc.edu` provider hint is usability only. Server access checks require verified Google identity, a confirmed `bc.edu` email, active membership, and an active linked profile.
- `GET /auth/callback` exchanges the OAuth code with PKCE, then redirects to `/dashboard`, `/access-pending`, or a safe sign-in error. Redirect origins come from validated `SITE_URL`; optional `next` destinations are restricted to local dashboard paths.
- `getCurrentAccess()` returns `signedOut | pending | active` (`pending` is the internal name for a signed-in person who is not on the staff list; the page says "Access not approved"). It claims a matching staff-list entry first. Active access carries user ID, profile ID, display name, and role. `requireActiveMembership()` redirects denied identities; dashboard layout and page both call it.
- `public.current_profile()` is a parameterless database function returning only the active caller's profile ID/display name. Its grants, fixed search path, and membership filter are authoritative in the migration. It never exposes identity links from other profiles.
- Sign-out is a server action that clears the local Supabase session. Session cookies are HttpOnly, SameSite=Lax, and Secure on HTTPS origins; the foundation browser client performs anonymous reads only.

## Implemented administrator membership operations

`list_staff(p_limit,p_search,p_role,p_state,p_after_email,p_after_key)` returns at most 51 safe summaries of members and listed (not yet signed-in) people to an active administrator. State is `all | active | inactive | invited`; role validation follows `public.app_role`; search matches email or public name literally; the keyset cursor orders by lowercase email and key. `staff_summary()` returns counts for administrators, editors, authors, invited and inactive. The pending-approval directory (`list_membership_candidates`) no longer exists. Administrators add people with `invite_staff(request_id, entries)` (up to 200 `{email, role, displayName?}` entries, `@bc.edu` only, no duplicates). Existing members and unchanged listings are returned in `skipped`; updates include role and display-name changes. Administrators manage listed roles with `change_invitation_role` and remove listings with `remove_invitation` (expected version, request id). All use the membership advisory lock and request receipts: exact retries replay, a reused request id with different content returns `request_conflict`. A signed-in person's own session calls `claim_invitation()`, which requires the same Google-only confirmed `bc.edu` identity as dashboard access and turns a matching live listing into a membership and profile (new profile name from the first supported value in the listing, Google profile, and email local part, with “Staff member” as the fallback); it returns false when nothing matches and stores nothing about unlisted people. Existing member role changes and deactivation keep `change_membership_role` and `deactivate_membership`; `approve_membership` requires a positive expected version and reactivates only an existing inactive member. See the [staff model plan](superpowers/plans/2026-11-16-staff-model-and-desk-simplification.md). `list_membership_audit_events` retains its bounded legacy response. `list_membership_audit_events_v2` adds nullable role detail and `membership.reactivated`, includes prior listing events for the same address, and remains administrator-only. Neither reader changes Task 8's article audit scope.

`approve_membership(targetUserId,requestId,role,displayName,expectedVersion)` requires a positive version and an existing inactive membership for a confirmed BC Google Auth identity. It reactivates that membership and retains existing profile public fields, creating a linked profile only if one is missing. It cannot create a membership for an unlisted identity; first-time membership creation happens through `claim_invitation()`. The former null-version write path is rejected, while an exact receipt created by that old path can still replay. `change_membership_role(targetUserId,expectedVersion,requestId,role)` and `deactivate_membership(targetUserId,expectedVersion,requestId)` require an active target and matching version. All derive the actor, reject ineligible/nonadministrator callers, and enforce last-admin protection under one transaction lock. Changed operations atomically write one allowlisted audit event and immutable exact-retry receipt. A no-op records only its receipt; stale or mismatched requests fail without state changes. The server action accepts only these strict command shapes and preserves the UUID on uncertain retry. Auth identities are never created or deleted by these operations.

## Implemented draft input validation

The validation module now lives at `src/shared/articles/draft-contract/draft-contract.ts`: `checkDraftInput(unknown)` returns `{ok:true,value:DraftInput}` or a safe `DraftFailure`; `isValidDraftDocument(unknown)` and `isValidDraftLink(unknown)` expose the same content/link rules for future adapters. Create/save command and result types live here; the RPC and server action implementations are documented below. The [accepted contract](superpowers/specs/2026-10-22-private-draft-workflow-design.md#draft-payload-and-content) remains authoritative for the grammar and bounds.

`supabase/migrations/20261022000000_draft_validation.sql` supplies private immutable invoker helpers `check_draft_input(jsonb)`, `is_valid_draft_document(jsonb)`, `is_valid_draft_link(text)` and their strict-key helper. They return canonical input or a validation failure without reading identity/catalog rows or writing data. UUIDs normalize to lowercase; category/tag IDs and profile/role credits sort deterministically. Display order is retained. Draft writes apply the same explicit edge whitespace and control character rules to metadata, body image alt text and captions in TypeScript and PostgreSQL. Link text and new return notes use the same control character rules. Interior spacing and multiline whitespace stay supported. Stored drafts and public articles keep their existing read rules so editors can load and repair older text. Lifecycle transitions continue to use the stored-content rules. Exact retries of committed writes still resolve using their existing receipts. Structural validation does not establish reference existence, activation or caller authority; Tasks 3–4 must enforce these under transaction locks.

The TypeScript byte helper counts JSONB spaces, string escaping and UTF-8 for JSON-safe integer values, rejecting incompatible Unicode, non-JSON values and excessive processing before content traversal. SQL applies bounds to actual JSONB serialization. JavaScript NULL denotes an incomplete body and corresponds to SQL NULL for the standalone document validator; JSONB `null` is not a document envelope. The enclosing request explicitly accepts `content: null` in both implementations. PostgreSQL rejects NUL/invalid surrogate encodings before a JSONB function can run. No raw HTML renderer, persistent draft writer or callable validation endpoint is enabled.

Internationalized hostnames, including all case-insensitive `xn--` labels, are deliberately rejected under the owner-approved Phase 3 restriction. Reintroducing them later requires matching standards-based validation at both boundaries; the document/editor architecture remains unchanged.

## Implemented owner article lifecycle

`publish_article(article_id,expected_version,request_id)` and `archive_article(article_id,expected_version,request_id)` accept the strict `ArticleLifecycleCommand` through separate server actions; `submit_article` (same arguments) and `return_article` (plus a required note of 1–500 characters) complete the review workflow. Who may call each is decided by `private.article_authority`: authors submit their own drafts, editors publish or return articles in review and archive their own publications, administrators do everything; credits grant no authority. `list_review_articles()` returns the review queue to editors and administrators only, with separate limits of 50 oldest pending submissions and 50 newest articles published by the caller. Publish requires a draft with a supported nonblank body, active references, finalized body media and a finalized main image with alt text and credit. Archive requires published status but does not recheck readiness, so invalid old content can leave circulation. Both require the current version, preserve slug/owner, increment once, capture a complete revision and an allowlisted audit event, and store an exact replay receipt atomically. A successful response contains `articleId`, `status`, `version`, `updatedAt`, `changed`, and `replayed`; failures use the bounded draft error codes. Exact retries return their original receipt after later changes. No public read grant is implied.

## Bounded public search

Phase 5 Task 17 implements POST RPC `search_public_articles(p_query text, p_limit integer default 12, p_cursor jsonb default null)`. Invalid requests consume no tickets, and admitted failures retain their ticket. Direct GET/HEAD cannot produce search results. Task 18 owns the GET page/UI. Hidden authors retain a plain-text byline and their articles remain public. The owner slug may be null and a sitemap article can have zero author URLs. Profile photos are served with private/no-store so moderation takes effect on the next request.

The service-only `sweep_orphan_guest_credits` RPC deletes up to 100 qualifying 30-day-old profiles per call and returns counts. Creation receipts survive the sweep. Exact replay of a swept credit returns `expired`; the editor can issue a new credit request. The scheduled route checks the configured production cron secret before creating a service client.

## Editorial article preview

`GET /dashboard/articles/[id]/preview` renders the latest saved draft that the current active editor or administrator can edit. Opening it writes no article, revision, or lifecycle state. The route has a generic noindex title and uses private, no-store responses. Protected images use the existing authenticated article media endpoint. The preview shows the saved publication date, or today's Eastern date as an estimate. An unknown draft, a draft outside the caller's edit access, and a published or archived article use the same missing response. Signed-out readers use the dashboard sign-in flow.
