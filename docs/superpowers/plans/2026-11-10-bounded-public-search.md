# Phase 5 Task 17 — bounded public search

Status: implementation on `feat/bounded-public-search`, based on Task 16 PR #65 (open). Target main; #65 remains a prerequisite while open. Task 18 owns the GET search page/UI.

## Requirements and design risks

- Expose one POST-capable `search_public_articles(query,limit,cursor)` RPC with strict typed inputs, public cards only and query-bound newest-first keyset continuation. Reuse the private candidate and batch card projections in one statement snapshot. No bodies, generated snippets, workflow/Auth fields or direct private-helper grants.
- Bound raw input to 512 Unicode code points/2,048 UTF-8 bytes, canonical whitespace-normalized input to 160 code points, and native simple-parser output to 1–8 distinct words of at most 120 code points each. Preserve query case in cursor identity; matching remains native case-normalized. A fixed explicit whitespace set is shared by SQL/TypeScript. Quotes, wildcard-looking text and hostile syntax remain literal data, never SQL/search operators. Reject malformed/control/empty/punctuation-only input and invalid/repeated/cross-query cursors before quota or search work. Limits default to 12/max 24; read at most one extra candidate.
- Enforce the approved shared 120-attempt/60-second fixed window inside the database, regardless of caller identity/IP, direct RPC, headers or requested count. A private cache-1 sequence encodes server minute and used attempts in a 128-value bucket. Its nontransactional increments survive ordinary rollback, failed/cancelled search and response loss; no caller may select/update/use it. A reserved transaction advisory lock serializes admission and the search transaction, avoiding session-lock leaks. It is deliberately global and serialized: measure bursts and queue behavior. Rate-limited calls return a safe 1–60-second retry value without running candidates.
- Compute the current window after acquiring the lock. Never move a future counter backwards if wall clock regresses. Counter persistence is rate-control state, not a durable business audit; database-crash sequence gaps/state uncertainty remain operational monitoring concerns. Invalid requests consume no attempts; admitted failed searches do.
- Bind successful execution to trusted PostgREST request.path/method for this direct POST RPC, so GraphQL/nested RPC calls cannot skip the gateway's function-setting boundary. Caller headers do not supply those trusted settings. Raw SQL tests explicitly simulate request context; anonymous/authenticated roles have no login credentials.
- Set the RPC's statement_timeout to two seconds and verify PostgREST actually hoists it before the main query. Do not infer a deadline from function SET alone in a raw SQL session. The server adapter also aborts transport after three seconds; request-local caching deduplicates metadata/page reads without refunding or persisting results across requests. Timeouts raise a fixed no-store HTTP 503 error that aborts the whole RPC transaction; do not swallow cancellation and allow later bulk calls to continue. The adapter maps it to unavailable. Test table-lock timeouts, caller aborts, explicit cancellation and rollback; verify counter consumption and lock release, including anon/authenticated direct HTTP requests. If deployment disables hoisting or cancellation defeats bounds, treat that as a search launch blocker. Pool-acquisition time and general request floods require hosted monitoring/edge controls; the shared quota is not per-IP protection.
- Keep volatile quota and immutable search data separate. Successful output and all failure/limited states are no-store. GET/HEAD RPC requests cannot run successful search in a read-only transaction; Task 18 will exercise the native GET page via this same server adapter. Structured RPC throttling uses the existing 200/envelope convention; future page feedback consumes retryAfter. No unrequested HTTP API route/UI.
- Preserve all existing content, grants, private editing/version/retry/history/media behavior. Add only private quota state and a narrow public execution grant. The anonymous publishable-key client never reads cookies/service credentials. Maintain safe rollback: revert consumers first, revoke the new RPC and retain derived quota/index state; no source rewrite or broad grant rollback.
