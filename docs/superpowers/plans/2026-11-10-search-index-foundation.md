# Phase 5 Task 16 — searchable text and indexes

Status: implemented and locally verified on `feat/search-index-foundation`, based on Task 15 PR #64. Reader PRs through #64 are now merged; this task targets main.

## Design, risks and acceptance

- Add private immutable helpers and native GIN expression indexes only. Preserve all stored source fields, versions, timestamps, revisions, audit, grants and public projections. No generated column, duplicated joined-name document, external service or public search endpoint. Existing readers/writers work before and after this additive migration.
- Validate canonical v1/v2 bodies with the existing 1 MiB/5,000-node/depth-16 validator before extraction. Traverse document order; adjacent inline text joins without inventing word boundaries, while block/hard-break/caption boundaries separate words. Extract only text nodes and image captions. Ignore marks/URLs, asset IDs, alt attributes, arbitrary JSON keys, NULL and unsupported legacy bodies. Valid title/excerpt/meta-description remain searchable independently; SEO keyphrase and revision bodies are excluded.
- Use explicit `pg_catalog.simple` normalization, no English stop-word removal or stemming. Store normalized distinct word arrays in GIN expression indexes, preserving the initial all-words/newest-first contract without positions/ranking. The native vector-to-array fast path falls back to pinned immutable native parser/dictionary primitives if a valid large document exceeds PostgreSQL's single-vector size. Do not truncate body prefixes or reject otherwise valid editorial writes. Native lexemes of 2 KiB or more are not searchable; future query bounds must stay below that limit.
- Partial article index includes published rows only. Separate active profile/section/category name indexes and a tag-name index update with their own records. Candidate lookup reads current joins, active article owner/section, active credited writers and active same-section categories; no denormalized name/association refresh protocol exists to race or lose retries.
- Add a private candidate reader for 1–8 normalized words of at most 120 characters, returning at most 25 IDs in publication-time/ID order with a paired optional keyset cursor. Each word may match any supported source; all words must match across sources, with duplicate paths deduplicated. No public EXECUTE, identity argument, snippets, body or API envelope. Task 17 owns public grammar/envelopes, quotas, effective cancellation and final operational budgets.
- Test edit/archive/restore, current name/association changes and visibility at query time. Already-running statement snapshots and MVCC index tuples are not a recall/physical-erasure promise. Existing transaction/retry/version behavior is unchanged; expression index maintenance is part of source transactions.
- Prove a populated upgrade preserves source hashes and an independent clean migration works. Standard index creation blocks writes while building; schedule a maintenance window for large catalogs and use short lock timeout so contention rolls back rather than hangs. Index failure must leave no partially applied migration. Rollback consumers first; remove only new indexes/helpers in a later migration, never source data or applied migration history.
- Measure real unforced plans on a representative synthetic corpus, rare/common/cross-field queries and maximum-size content. Bound input/output and source traversal; postings work remains corpus-dependent. Do not claim a private function SET establishes an effective statement timeout. Task 17 must prove cancellation/quota behavior before exposing search.
